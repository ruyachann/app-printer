# Phase 4: 通信キャプチャ用テスト計画

HCI Snoop Logは全テストの通信が1つのログファイルに連続して記録されます。
後でWiresharkで見たときに「どのパケットがどのテストか」を区別できるよう、
**印刷した順番と大まかな時刻**をこの表に記録してください（秒単位まで正確でなくてOK、前後の見分けがつけば十分です）。

## 既知の注意事項

プリンターの給紙モーターに不具合があり、印字動作音はしても紙が送られない症状が確認されています（ハードウェア側の問題と推測）。
**この作業では紙に実際に印字されるかどうかは問いません。** Bluetooth通信さえ発生していれば、HCI Snoop Logに記録が残り解析に使えます。
気にせずこのままテストを進めてください。

## 実施ルール

- 1回の印刷で変更する要素は1つだけにする
- 印刷ごとに少し間隔をあける（数秒）と、後でログを見分けやすくなります
- 順番は変えないでください（下の表の順で実施）

## 画像テスト（I01〜I06）について：優先度低下・任意

文字印刷のキャプチャ解析により、文字自体が疎な1bitビットマップとして送信されていることが判明したため、
文字キャプチャを画像プロトコル解析のサンプルとして活用できます。そのため、専用の画像テストキャプチャは
**必須ではなくなりました。** 解析用端末（Android 7.0）の性能不足で「画像」メニューがフリーズする問題もあるため、
無理に実施する必要はありません（余裕があれば任意で試す程度で構いません）。

T01〜T08, Q01〜Q04まで全て完了。プロトコル解析の結果、対応表は `captures/rfcomm_jobs/README.md` を参照。
画像テスト（I01〜I06）は文字・QRの解析結果から画像プロトコルを導出できたため実施不要と判断。
